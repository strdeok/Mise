# 2026-10-14 — Mise Table UI/UX 전수 조사

## 결론

Mise의 흑백 목록, 하나의 집중 행동, 시간표, 아날로그 타이머라는 기본 구성은 유지할 가치가 있다. 가장 큰 개선점은 **같은 할 일·시간·상태가 작성 → 계획 → 집중 → 저장 → 회고까지 이어지게 만드는 것**이다. 먼저 동작과 정보의 신뢰성을 고치고, 그 위에서 읽기·터치·입력·움직임을 정리한다.

중복을 합친 개선 항목은 **48개: P0 0개, P1 16개, P2 28개, P3 4개**다. P1은 모두 지금 즉시 구현한다는 뜻이 아니다. 현재 기능의 결함과 MVP-1 접근성 작업을 아래에서 구분했다. 실제 기기에서 데이터 손실이나 전체 작업 불능을 재현하지 않았으므로 P0로 부풀리지 않았다.

## 조사 방법과 한계

- 방법: 독립된 두 검토를 합성했다. A(`/root/design_review`)는 정보 구조·흐름·문구·인지 부담, B(`/root/native_audit`)는 네이티브 접근성·레이아웃·모션·소스 구조를 검토했다. 두 검토는 서로의 결과를 보지 않았다. 이후 주 검토자가 화면 관찰과 레퍼런스를 대조했다.
- 적용 스킬: `ui-ux-pro-max`, `impeccable`, `animate-expo`. Impeccable의 native audit 기준을 적용했으므로 웹용 DOM detector·오버레이를 네이티브 품질 증거로 사용하지 않았다.
- 실제 화면: iPhone 17 Pro / iOS 26.4 / Expo Go의 활성·목표 초과 타이머, 타이머 설정, 전체화면을 확인했다. Today는 이번 대화에서 앞서 실행 확인한 화면도 참고했다.
- 보조 화면: React Native Web을 390×844로 확인했다. Today, Todo 목록·상세·수정·행 메뉴·카테고리 관리, 월·주·일 일정과 일정 수정, 통계, 설정, `/timer` 직접 진입을 확인했다. 웹 관찰을 iOS·Android 재현으로 바꾸어 쓰지 않았다.
- 소스: 활성 5개 탭, Timer, 공통 입력·버튼·시트·메뉴, 상태 저장·복원, 시간/통계 계산과 앱 설정을 검토했다. 미사용 `AppTabs`, 예전 `Schedule`/`TimetableBlock`, 템플릿 아이콘을 현재 화면의 결함으로 세지 않았다.
- 근거 표기: **S** 소스에서 확인, **V-iOS** 네이티브 화면 관찰, **V-Web** 웹 화면 관찰, **R** 런타임 추가 확인이 필요한 위험. S는 실제 기기의 잘림·프레임 저하·스크린리더 낭독을 측정했다는 뜻이 아니다.
- Android, 360px 네이티브, 시스템 글자 확대, VoiceOver/TalkBack, 실제 기기 알림, 출시 빌드 성능은 미검증이다. 이번 작업은 조사이며 프론트엔드 구현·테스트·의존성 추가는 하지 않았다.
- 기존 2026-10-11 디자인 스냅샷은 작업 공간에서 삭제 상태여서 현재의 시각 증거로 사용하지 않았다. Expo Go의 파란 개발 메뉴·웹 LogBox는 제품 디자인 요소에서 제외했다.

## 제품 기준과 범위

기준은 `AGENTS.md`, `docs/sdd/product.md`, `docs/sdd/planning/release-roadmap.md`, `docs/sdd/design/mobile-ui-direction.md` 및 10월 10·11·14일 작업 일지다. 현재는 MVP-0 로컬 앱이다.

문서 사이에 충돌이 있다. AGENTS와 product는 흑백을 요구하지만 mobile-ui-direction과 구현은 일정·통계의 여러 색, 빨간 다이얼과 따뜻한 손잡이를 허용한다. 이번 조사에서는 상위 흑백 지침을 기준으로 판단했다. 후속 구현 전에 디자인 문서를 같은 기준으로 맞춰야 한다. 이전의 명시적 색상 결정이 있다면 그 근거를 계획·SDD에 먼저 연결해야 한다.

범위 표기:

- **현재**: 기존 MVP-0 기능의 오류·모순·조작 개선.
- **MVP-1**: 접근성 전반, 첫 실행/빈 상태 전반, 초안 보존 등 로드맵의 다음 단계. 기존의 잘못된 안내만 바로 고치는 것은 현재 범위로 볼 수 있다.
- **제품 결정**: 태블릿·가로 화면·다크 모드처럼 이번 조사만으로 추가하지 않는 지원 범위.

OAuth·서버·동기화·외부 캘린더·반복 일정·위젯·AI·새 통계 지표는 제안하지 않는다. 기존 검색/선택 UI를 개선하는 것과 Release-3 전역 검색 기능을 추가하는 것도 구분한다.

## 보존할 강점

1. Today의 검은 집중 카드와 구분선 목록은 주요 행동을 빠르게 찾게 한다. 5개 라벨 탭과 7열 주간 시간표는 현재 제품 계약에 맞는다.
2. 공통 SheetCard, Safe Area, 키보드 회피, 스크롤, 벡터 화살표, Todo checked/expanded 상태와 일부 명확한 라벨은 좋은 출발점이다.
3. Timer의 준비·시작·일시정지·재개·완료·폐기가 분리돼 있고, 전체화면은 세션을 바꾸지 않는다. Android 뒤로가기로 전체화면부터 나가는 처리도 있다.
4. UI → Zustand → Domain → Repository 경계가 유지된다. 후속 개선도 이 경계를 따라야 한다.

## 잠정 평가

디자인 특성은 ‘조용한 하루 브리핑 + 시간표 + 집중 도구 + 회고’로 드러난다. 문제는 개별 화면보다 연결이다. 날짜, 할 일, 설정 시간, 실제 기록을 사용자가 화면 사이에서 다시 맞춰야 한다.

## 모션 조사 — animate-expo 적용

| 사용 빈도 / 목적 | 판단 | 후속 구현 기준 |
| --- | --- | --- |
| 탭, 스크롤, 설정 토글 / 반복 조작 | 콘텐츠 재등장·슬라이드 추가하지 않음 | 탭은 즉시 전환하고 맥락 유지. native 기본 동작 우선 |
| 버튼·행 선택 / feedback | 거의 느껴지지 않는 press-in 응답 | 기존 Reanimated 재사용, transform/opacity, 대체로 150ms 미만. 작은 타깃은 scale보다 면/불투명도 |
| 시트·메뉴 / spatial consistency | 표준 전환을 유지하며 감소 설정 대응 | native 전환 우선. dismiss가 초안을 버리는 동작인지 먼저 정의 |
| 일정 이동 / finger tracking | 현재 JS 드래그를 우선 개선 | Gesture + shared value + UI thread, 의도적 활성화, 손을 뗄 때 한 번 커밋, 속도·취소·복귀 확인 |
| 목표 도달·완료 / state indication | 수치 결과와 상태 전달 우선 | 반복 축하/매초 펄스 금지. 기록 확인 후 다음 행동 |

Reanimated 4/React Compiler에 맞는 get/set API와 실제 설치 버전을 구현 시 확인한다. 해당 API 형태만으로 현재 시각 오류나 프레임 저하가 입증되는 것은 아니다. 햅틱·키보드 제어·새 시트 라이브러리는 지금 추가할 필수가 없다. 움직임의 ‘느낌’은 Simulator/Expo Go로 검증 완료할 수 없고 사용자가 가장 느린 지원 기기의 출시 빌드에서 확인해야 한다.

## 인지 부담과 사용자의 감정 흐름

- 첫 사용자: 설정의 정적인 화살표, Todo 상세의 집중 부재, 구현 용어 때문에 다음 행동을 추측한다. 현재 선택과 실제 동작을 일치시키는 것이 첫 개선이다.
- 여러 일을 오가는 사용자: 미래 날짜/통계 기간을 탭 이동 때 잃고, 중복 작업명과 긴 평면 picker에서 다시 찾는다. 맥락 보존과 경로가 필요하다.
- 큰 글자·보조 기술 사용자: 23dp 체크, 이름 없는 Switch, 선택 상태 누락이 핵심 루프를 어렵게 한다. 목록 밀도를 유지하면서 실제 조작 영역과 의미를 확보해야 한다.
- 완료 직후: 큰 장식보다 ‘어떤 작업에 몇 분을 기록했는가’가 안심을 준다. 그 다음 휴식/집중을 안내한다.
- 작업이 많은 날: N개 Todo를 동등하게 나열하거나 부모/자식을 평평한 통계로 보여주는 부분이 부담을 만든다. 5개 탭·7일 날짜 자체는 제거할 대상이 아니다.

## 별도 제품 결정과 QA 항목 — 48개 결함 수에 미포함

- **태블릿/가로/다크 지원:** 현재 portrait/light 설정은 명시적이다. 이를 미구현 기능 결함으로 세지 않았다. 지원한다면 static pageGutter, 미사용 contentMax, window width 기반 주간 폭을 부모 측정/반응형 구조로 바꾸는 작업을 계획한다.
- **Android predictive Back:** app.json에서 false다. 보통 Back이 깨졌다는 증거는 없다. 지원 Android/Expo 기준을 확인한 뒤 전환 preview와 Modal/fullscreen/root의 Back을 검증한다.
- **72시간대 활성 기록:** iOS에 기존의 긴 활성 세션이 표시됐다. 앱 재시작 뒤 계속 측정하는 계약상 가능한 값이므로 자동 종료·상한을 임의 추가하지 않았다. 오래된 세션의 안내/회복 정책은 별도 논의할 수 있다.
- **실제 기기 체크:** 360/390 폭, 큰 한글 이름·카테고리, iOS 큰 글자/Android font scale, 키보드/Modal/뒤로가기, 5분 연속 일정, 알림 거부/재허용, cold notification launch, 저장 실패, 출시 빌드의 이동/스크롤 성능.
