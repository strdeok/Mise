# 모바일 UI 방향

Mise의 MVP-0 화면 구현에 적용하는 모바일 UI 원칙이다. 이 문서는 화면 구조와 상호작용의 기준이며, 도메인 규칙과 데이터 계약을 바꾸지 않는다.

## 공통 원칙

- 흰 배경, 검은 주요 행동, 회색 구분선만 사용한다. 상태를 색으로만 구별하지 않는다.
- 모바일 한 손 조작을 기준으로 하단 탭과 주요 버튼에 충분한 터치 영역을 둔다.
- Safe Area를 포함해 상단의 맥락 정보와 하단의 탭 바가 겹치지 않게 배치한다.
- 정보는 카드의 반복보다 제목, 얇은 구분선, 여백으로 계층을 만든다.

## 화면별 패턴

| 화면 | 적용 패턴 | 사용자 행동 |
| --- | --- | --- |
| Today | 지금 할 일과 다음 일정 중심 브리핑 | 검은 집중 카드에서 바로 Focus를 시작하거나 진행 중인 타이머를 연다. |
| Todo | 제목부터 적는 빠른 입력 | 필요할 때만 카테고리와 상위 Todo를 펼친다. |
| Schedule | 월간 기본, 주간·일간 전환 | 달력에서 날짜를 고르고, 시간표에서 계획을 배치한다. |
| Timer | 아날로그 다이얼과 포모도로 순환 표시 | 시간은 다이얼 아래에서 읽고, Focus와 휴식 순서를 한눈에 확인한다. |
| Stats | 계획 대비 실제 시간 회고 | 기간을 바꾸며 계획 안·밖의 집중 시간과 Todo별 사용 시간을 비교한다. |

## 레퍼런스 해석

- Things와 Structured의 조용한 Today 흐름을 참고해, 하루의 목록보다 현재 할 일을 먼저 보인다.
- Todoist Quick Add처럼 제목 입력을 먼저 열고, 선택값은 점진적으로 노출한다.
- Structured·Routine·Notion Calendar의 달력과 시간표 전환 구조를 참고한다.
- Session의 시각 타이머 표현과 Sunsama의 계획 대비 실제 회고를 Mise의 흑백 토큰으로 재해석한다.

## 검증 기준

- 360px와 390px 폭에서 제목, 시간, Todo 행의 텍스트가 잘리지 않는다.
- 선택·진행·완료 상태는 아이콘, 텍스트, 채움으로 구분한다.
- iOS와 Android에서 Safe Area, 키보드, Modal, 뒤로가기 후에도 주요 행동이 가려지지 않는다.
