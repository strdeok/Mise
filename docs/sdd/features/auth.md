# 인증

**우선순위:** Google·Kakao P0, Apple 후속 P1. **목적:** OAuth 2.0/OIDC 기반 외부 제공자 로그인으로 사용자별 서버 데이터를 분리하고 앱 재실행 시 로그인 상태를 복원한다.

## 사용자 시나리오와 입출력

사용자는 MVP에서 Google 또는 Kakao를 선택해 인증한다. Apple은 후속 제공자다. App은 시스템 브라우저를 통한 OAuth 2.0 Authorization Code + PKCE 흐름을 사용한다. Google과 Kakao에서 OIDC를 사용하고 Server가 제공자 ID Token을 검증한 뒤, 내부 사용자를 찾거나 처음이면 생성해 Mise Table Access/Refresh Token을 발급한다. 성공하면 Today로 이동한다. 앱 재실행 시 내부 토큰으로 세션을 복원하고 Settings에서 로그아웃한다.

## 정상·예외 흐름

- 첫 로그인: 검증된 `provider`와 제공자 고유 사용자 ID로 기존 연결을 먼저 찾는다. 연결이 없고 제공자가 확인한 이메일과 같은 이메일의 내부 계정이 있으면 새 계정·내부 토큰을 만들지 않고 `이미 동일한 이메일의 계정이 있습니다. 기존 로그인 방식으로 로그인해 주세요.`라고 안내한다. 이메일만으로 계정을 자동 병합하지 않는다. 중복 계정이 없으면 내부 사용자 및 기본 Settings를 생성한다.
- 제공자가 확인한 이메일이 없으면 이메일 일치 여부를 판정하지 않고 제공자 고유 ID 기준으로 처리한다. 동일 이메일 충돌은 입력한 로그인 제공자와 기존 제공자가 다를 때에도 적용한다.
- MVP에서는 기존 계정에 다른 로그인 제공자를 추가하거나 두 계정을 병합하지 않는다. 동일 이메일 안내를 받은 사용자는 기존에 사용하던 제공자로 로그인한다. 다른 제공자 연결·해제 화면은 제공하지 않는다.
- 재로그인: 같은 제공자 고유 사용자 ID를 기존 내부 사용자에 연결하고 내부 Access/Refresh Token을 발급한다.
- 만료: Access Token 만료 시 갱신을 시도한다. 갱신 불가 시 인증 정보를 제거하고 로그인 화면으로 이동한다.
- Access Token 유효기간은 15분, Refresh Token 유효기간은 30일이다. 갱신할 때마다 Refresh Token을 교체하고 이전 토큰을 폐기한다.
- 로그아웃: 현재 기기의 Refresh Token을 폐기하고 기기 저장 인증 정보를 제거한다. 다른 기기의 로그인과 사용자 데이터는 유지한다.
- 계정 삭제: 최근 인증과 최종 확인 후 내부 계정 및 연결 데이터를 삭제한다. 모든 기기의 Refresh Token이 무효화된다. 앱은 삭제 성공 후 기기 인증 정보를 제거한다.
- 제공자 취소·거부·검증 실패: 내부 세션을 생성하지 않고 구분 가능한 오류 또는 안내를 표시한다.

## 권한과 연결

로그인 이후의 개인 리소스는 인증 사용자의 소유권을 서버에서 검증한다. 제공자 토큰을 Mise Table API 토큰으로 그대로 사용하지 않는다. Refresh Token은 App의 SecureStore에 보관하고 서버에는 해시만 저장한다. 교체된 Refresh Token의 재사용은 거부한다. `AUTH-01`~`AUTH-09` 규칙, `/auth/*`·`/users/me` 계약, `AC-AUTH-*`를 참조한다.

변경 결정: OAuth 기반 로그인으로 전환. 기존 [기능 명세서](../reference/feature-requirements.txt) §5의 이메일·비밀번호 가입과 소셜 로그인 P1 분류는 이 결정으로 대체한다.
