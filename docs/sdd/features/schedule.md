# Schedule

**우선순위:** Day View·CRUD P0, 제스처 편집 P1. **목적:** 하루 계획을 시간 블록으로 표현하고 Focus 기록과 연결한다.

## 시나리오와 입출력

사용자는 날짜를 고르고 블록을 생성·수정·삭제한다. 로컬 프로토타입의 입력은 `dateKey: YYYY-MM-DD`, `startMinute`, `endMinute`, 선택 `todoId`, `title`이다. `startMinute`·`endMinute`은 해당 날짜의 자정부터 지난 분이다. 출력은 시간순 블록과 현재 시각, 블록별 계획·실제 시간이다.

## 정상·예외 흐름

- 로컬 프로토타입은 기기 현지 날짜 `dateKey`와 자정 기준 분을 저장한다. 서버 연결 시에는 기존 `date`·`startAt`·`endAt`·`timezoneId` 계약으로 변환한다.
- `0 <= startMinute < endMinute <= 1440`, 5분 단위, 최소 5분을 만족해야 한다. 같은 `dateKey`의 삭제되지 않은 다른 블록과 겹치면 저장할 수 없고, 앞 블록의 종료와 다음 블록의 시작이 같으면 허용한다. 자정을 넘는 블록은 만들 수 없다.
- Todo 없는 임시 블록을 허용한다. Todo 연결 시 기본 제목은 Todo 제목이다.
- 블록에서 Focus를 시작하면 Session에 `scheduleBlockId`를 남긴다. Todo가 없는 블록이라면 App이 먼저 Todo 선택을 요청한다. 서버는 선택한 Todo를 블록에 연결하면서 Focus Session을 시작한다. 이미 Todo가 연결된 블록에서는 그 Todo로 시작한다. Todo에서 직접 시작한 Focus는 계획 외 기록이다.
- 블록 삭제는 soft delete다. 연결 Todo나 이미 기록된 Session을 삭제하지 않는다. 삭제된 블록에 확정 기록 시간이 0초보다 큰 완료 Focus가 연결돼 있다면 마지막 계획 시간을 계획·실제 비교에 남긴다. 그렇지 않으면 삭제된 블록은 계획 시간 합계에서 제외한다.
- 블록 수정은 과거 통계에도 반영한다. 연결된 Focus가 있어도 블록의 날짜·시작·종료를 수정할 수 있으며, 계획 대비 실제 비교에는 수정 후 블록의 최신 날짜와 계획 시간을 사용한다. Focus Session의 실제 기록 시간과 시작 날짜는 바꾸지 않는다.
- 모바일 P0의 입력·수정은 탭과 시간 선택으로 완결된다. 드래그 이동·길이 변경은 P1이다.
- 블록을 저장할 때 기기 시간대와 UTC 오프셋을 함께 저장한다. 나중에 기기 시간대가 달라져도 과거 블록은 마지막 저장 당시의 현지 시각과 시간대 표시를 유지한다.
- App은 겹침을 미리 안내하고 Server는 생성·수정 시 다시 검사한다. 두 기기에서 동시에 저장해도 겹치는 블록이 함께 확정되지 않도록 DB 제약으로 보호한다. soft delete된 블록은 새 일정의 겹침 검사에서 제외한다.

본인 소유 블록과 Todo만 참조할 수 있다. `SCHEDULE-01`~`SCHEDULE-05`, `TIME-01`~`TIME-02`, `/schedule*`, `AC-SCHEDULE-*`를 참조한다.
