# Settings와 알림

**우선순위:** P0. **목적:** 새 세션의 기본 시간과 표시 방식을 정하고 목표 시간 도달을 알린다.

## 설정

기본값은 Focus 25분, Short Break 5분, Long Break 15분, `countdown`이다. 사용자는 각 시간, `countdown`/`elapsed`, Focus·Break 종료 알림 여부를 변경한다. 변경값은 새 세션부터 적용하고 실행 중 세션의 목표 시간은 변경하지 않는다. 계정 화면에는 현재 로그인 제공자와 제공자가 제공한 이메일(있는 경우)을 읽기 전용으로 표시하고 로그아웃·계정 삭제를 제공한다. MVP에는 제공자 연결·해제 기능이 없다.

## 계정 삭제 (P0)

Settings에서 삭제를 시작하고 최근 인증 확인과 최종 확인을 거친다. 서버가 본인 계정과 연결된 Todo, 오늘 지정, Schedule Block, Session·요청 기록, Settings, 인증 연결, Refresh Token을 삭제한다. 통계는 Session에서 계산하므로 함께 사라진다. 삭제 성공 후 App은 인증 값을 제거하고 이 기기의 예약 알림을 취소한다. 삭제 실패 시 성공한 것처럼 로그아웃·삭제 완료로 표시하지 않는다. Google Play 제출에는 앱 외부에서도 삭제를 요청할 수 있는 웹 링크를 제공한다. 이 링크는 별도 웹 앱이 아닌 간단한 요청 경로로 구성할 수 있다.

## 알림 흐름

필요한 시점에 OS 알림 권한을 요청하고 권한 상태를 Settings에 표시한다. 거부돼도 타이머는 동작한다. Session 시작·Resume 시 기기의 예약 알림에서 같은 Session ID의 기존 알림을 정리하고 남은 목표 시간에 맞춰 하나를 예약한다. Pause·Complete·Discard 시 해당 알림을 취소한다. 알림을 누르면 관련 Timer 화면으로 이동한다. 서버 Push는 P2다.

앱 재실행·재설치 후에는 서버 활성 Session과 기기의 예약 알림 목록을 대조한다. 목표 시각이 남은 RUNNING 세션이면 이 기기에 알림 하나를 확보하고, 이미 지났다면 새 알림을 만들지 않고 목표 시간 처리 화면을 보여준다. 서버 DB에는 OS 알림 ID를 저장하지 않는다.

알림 예약은 앱의 부수 효과이며 서버 상태를 바꾸지 않는다. 서버 전이가 실패했다면 예약·취소 결과도 서버 상태에 맞춰 재조정한다. `SETTINGS-01`~`SETTINGS-02`, `NOTIFY-01`~`NOTIFY-04`, `/settings`, `AC-NOTIFY-*`를 참조한다.

로컬 알림은 기기별로 관리된다. 다른 기기에서 세션을 변경한 동안 현재 기기가 백그라운드에 있으면 이미 예약된 알림을 즉시 원격 취소할 수 없다. 앱 복귀 시 서버 상태와 대조해 정리한다. 기기 간 즉시 취소는 Push 도입 시 재검토한다.
